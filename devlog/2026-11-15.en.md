# 2026-11-15: the controller was the hard part

## Today's conclusion

The games were not the problem; the input was. On the R36S the analog stick (`adc-joystick`) and
the buttons (`gpio-keys`) are **two separate input devices**, and SDL/RetroArch will not merge
them. Pick the stick device and every button is dead; pick the button device and the stick is dead.

## The black screen was not the core

Switching from the vendor `gpsp_ezode_mod` core to a standard `gpsp` still produced a black screen,
with `c_RkRgaBlit failed` repeating in the journal every frame. The vendor RetroArch is linked
against `librga.so.2` and copies frames with Rockchip's private 2D blitter; mainline has no RGA
driver. **Fix:** replace the emulator with Debian's stock RetroArch 1.20, which renders through KMS
and panfrost like any other application.

Second trap: the launcher inherited `LD_LIBRARY_PATH=/opt/treeos-compat/lib`, whose old `libva`
shadowed the system library and caused a `vaMapBuffer2` symbol error and an immediate exit.
`unset LD_LIBRARY_PATH` in the launcher fixed it.

## Input: from virtual gamepad to virtual keyboard

The first attempt merged both devices into a virtual gamepad in user space, but the button indices
RetroArch assigned to that device did not match anything we could derive from the kernel key codes.
The working approach is a **virtual keyboard**: `padmerge.py` translates physical buttons to
keyboard keys, and RetroArch uses explicit bindings such as `input_player1_a = "x"`. The analog
stick becomes arrow keys once it leaves a dead zone.

Captured key codes on the unit (read from the event stream, not decoded from sysfs): A=305, B=304,
X=307, Y=308, L1=310, R1=311, d-pad 544-547, Select=704, Start=705, L3=706, R3=707, FN=708.

## A save file overwritten with empty data

One 128 KiB save became all `0xFF`. Chain: save sorting had moved the file into a `gpSP/`
subdirectory, the game loaded an empty save from the expected path, and on exit the emulator wrote
that empty state back. The file was restored from an offline copy. **Root cause is not proven**;
disabling sorting and keeping saves in the content directory is a mitigation, not an explanation.

## Chinese file names inside ZIPs

A ZIP whose entries use GBK-encoded names fails to extract under RetroArch's UTF-8 handling (the
log shows a mojibake path). Extract with an explicit GBK decode, then move the original archive out
of the scanned directory — otherwise the frontend lists both the archive and the extracted ROM.
