## 一、缺陷清单（现成系统上的实际毛病）

### D1 · 刷完不能直接开机（严重）

镜像刷进卡之后，`/boot` 里**没有 `boot.ini`、没有 `Image`、没有 `.dtb`**。
必须先回电脑跑一次 `dtb_selector`，它才会把这三样写进去。

不跑的结果：黑屏，`/boot/error.log` 里写着 `dtb load fail`。

**TreeOS 要求：刷完即开机，不允许有"第二步"。**

### D2 · 补启动文件时漏 `logo.bmp` → 开机全黑（严重）

`boot.ini` / `Image` / `.dtb` 齐了，但 `/boot/logo.bmp` 没有，**开机第一屏就是纯黑**。
素材明明躺在 `/boot/consoles/logo/<分辨率>/logo.bmp`，但没有程序会去拿。

**TreeOS 要求：出厂必须带 `logo.bmp`（640×480）。写进验收：任何时刻屏幕不许纯黑。**

### D3 · 系统菜单 26 个脚本，0 个中文（严重）

EmulationStation 界面已经是 `zh-CN`，但 `Tools` / `Advanced` 菜单里的条目**全部是英文文件名**：

```
ThemeMaster.sh   System Info.sh   File Manager.sh
Change Password.sh   Install to eMMC.sh   Ghost Loader.sh
Backup ArkOS Settings.sh   Controller Tester.sh   …
```

**实测：26 个脚本，含中文的 0 个。**

**TreeOS 要求：菜单项全部中文化，英文保留在文件里但不显示给用户。**

### D4 · ThemeMaster 断网就报错（中）

主题全在本地 `/roms/themes/`，但 ThemeMaster 的联网功能（在线主题库/预览图）会在没网时弹提示、挡路。

**TreeOS 要求：主题功能 100% 离线可用；联网只作为可选增强，断网不报错。**

### D5 · 刷机包是三层压缩（中）

```
.7z.001 + .7z.002 + .7z.003   →   合成一个 .img.xz   →   再解成 .img（12GB）
```

新手不知道要装 7-Zip、不知道要点两次、不知道分卷要放一起。

**TreeOS 发布形式要求：一个文件，双击即刷。解压交给工具，不交给用户。**

### D6 · glibc 2.30 天花板（严重，但暂时不解）

底座是 **Ubuntu 19.10，glibc 2.30，2020 年 7 月已停止支持**。

后果（另一个 session 实测）：
- 官方 Ruffle 全部要 glibc ≥ 2.32 → 装不上
- 新版 Chromium 要 ≥ 2.35 → 装不上
- 社区 AppImage 版能启动，但 Mesa 报 `DRI3 error`、无 Vulkan、**画面全黑**

**短期不换底座**（换 = 重做一个发行版），Flash 用社区 Ruffle Handheld 已跑通。
**长期必须换**，详见 `04_底座与运行时.md`。

### D7 · 没有安全更新（严重，长期）

Ubuntu 19.10 已 EOL 五年多。**这台机器联着 WiFi，跑着浏览器级的组件，却收不到任何安全补丁。**

这不是"能不能玩"的问题，是"敢不敢拿去卖"的问题。

| 编号 | 问题 | 定位 | 严重度 |
|---|---|---|---|
| **D8** | 主菜单**电量不显示** | ✅ 已修（2026-11-16）：两层原因——① `CONFIG_CHARGER_RK817=m` 但模块没装进卡，改为 `=y` 重编内核；② 驱动出来的是 `rk817-battery`，ES 只认 `battery`。新增 `treeos-battery.service` 把电量写到 ES 读取的 `/tmp/battery.percent`。实测 98% / Discharging 正常显示 | 中 |

| **D11** | **摇杆完全不能操作** | ✅ **已修复（2026-11-15）**：两层原因——①`CONFIG_JOYSTICK_ADC` 单独设置会被 olddefconfig 丢掉，因为父项 **`CONFIG_INPUT_JOYSTICK` 也没开**；两个一起开才生效（System.map 出现 11 个 `adc_joystick` 符号）。②设备有了之后 ES 仍不认，需在 `es_input.cfg` 写 `type="axis"` 配置（见下） | 严重 |
| **D10** | 主菜单 **Distro Version 不显示** | `/usr/share/plymouth/themes/text.plymouth` 存在且含 `TreeOS 0.1 (Debian 13)`，但 ES 仍显示空 | 低 |

| **D12** | **Flash 游戏里鼠标不动** | 🟡 已修待验证：Ruffle 的 gptokeyb2/冻结前端只认 SDL GameController，而本机输入被拆成两个设备（`adc-joystick` 只有轴、`gpio-keys` 只有键），SDL 不合并 → 轴被忽略。方案：内核开 `CONFIG_INPUT_UINPUT` + `stickmouse.py` 直接造一个 uinput 鼠标（摇杆=相对移动，A=左键，B=右键，方向键也走移动）。内核 #13 已编好并部署，待重启验证 | 中 |

| **D13** | **GBA 游戏黑屏** | ✅ 已修（2026-11-15）：默认核心 `gpsp_ezode_mod` 是 ArkOS 专用版，用 **Rockchip RGA 硬件加速**做画面转换；主线内核没有 RGA 驱动 → `c_RkRgaBlit failed` 刷屏、画面全黑。换成标准 `gpsp` 核心后正常。es_systems.cfg 备份为 `.bak.gba` | 严重 |

### D13 GBA 黑屏实录（2026-11-15）

- 现象：进 GBA 游戏屏幕全黑，但进程在跑、CPU 有占用、声卡 DRM 都正常。
- 证据：`journalctl -u treeos-emulationstation` 里 `treeos-es.sh[PID]` 不停输出
  `c_RkRgaBlit failed.` / `c_RkRgaColorFill failed.` / `fd-vir-phy-hnd-format[...]`。
- 原因：ArkOS 的 `gpsp_ezode_mod` 核心编译时绑定了 librga（厂商 4.4 内核的私有 RGA 驱动），
  主线 6.12 没有 rga 驱动，画面转换全部失败。
- 修复：`/etc/emulationstation/es_systems.cfg` 里 gba 的默认核心从 `gpsp_ezode_mod` 改为 `gpsp`。
- **排查同类问题的通用方法**：游戏黑屏但进程活着 → 先看 journal，有没有 `RkRga`/`mali`/`egl` 报错，
  再判断是不是 ArkOS 专用核心/库依赖了主线没有的厂商驱动。
- **改配置的坑（2026-11-15 亲测）**：ES 退出时会把内存里的 `es_systems.cfg` 写回磁盘，
  直接在 ES 运行时改，重启后被旧内容覆盖。正确顺序：`systemctl stop treeos-emulationstation`
  → 改文件 → `systemctl start`。改完确认 `sed -n "1433p"` 内容没被翻回去再进游戏。
- **真正的根因（2026-11-15 深挖）**：换核心到标准 `gpsp` **仍然黑屏**，RGA 报错不停。
  用 `--verbose` 跑发现 GL 上下文是好的：`Vendor: Mesa, Renderer: Mali-G31 (Panfrost)`，
  `OpenGL ES 3.1 Mesa 25.0.7`。问题在 **ArkOS 的 RetroArch 本体**：
  `/opt/retroarch/bin/retroarch` 链接了 `librga.so.2`（`ldd` 可见），每帧都调
  `c_RkRgaBlit` 把画面拷到显示层。主线内核没有 RGA → 每帧拷贝失败 → 黑屏，与核心无关。
  `sdl2` 视频驱动在此版本初始化失败（`Cannot open video driver`），`glcore` 未编译，
  只有 `gl` 且必经 RGA。
  **结论：不能用 ArkOS 的 RetroArch 本体，换 Debian 官方 retroarch 1.20（trixie 源里有）。**
- **最终修复（2026-11-15）**：`apt install retroarch`（1.20.0，源里就有）。
  实测 12 秒推送 515 帧、丢 1 帧，零 RGA 报错，GL 走 `Mesa / Mali-G31 (Panfrost)`。
  启动器 `/usr/local/bin/retroarch` 改为一行 exec `/usr/bin/retroarch`，
  旧 ArkOS 包装（含 glibc 2.42 loader 逻辑）备份为 `retroarch.arkos`。
  **以后新系统的默认启动器就是 Debian RetroArch，ArkOS 版只在排查时用。**
  注意：手动测试时必须先 `systemctl stop treeos-emulationstation`，否则 KMS 被 ES 占着会报
  `[KMS] Error when switching mode`。
- **第二个坑（2026-11-15，同日）**：换标准 RetroArch 后游戏**闪退**，屏幕黑一下、左上角有光标、
  回到 GBA 列表。journal 里真正原因：
  `/usr/bin/retroarch: symbol lookup error: libavutil.so.59: undefined symbol: vaMapBuffer2`。
  根因是 ES 的启动环境 `treeos-es.sh` 里设了 `LD_LIBRARY_PATH=/opt/treeos-compat/lib`，
  里面有 **旧 libva.so.2**（145KB vs 系统 675KB），覆盖系统新库。
  **修复：启动器里 `unset LD_LIBRARY_PATH`** 再 exec。
- **验证结果**：GBA 游戏正常出画面（2026-11-15 01:56 拙木确认"现在进来了，可以，非常好"）。
  同一份包装脚本里同时处理了 RGA 与 libva 两个坑，以后新核心/新系统先按此排查。

### D12 Flash 鼠标修复实录（2026-11-15）

- 日志里 `Input: native gamepad profile | right stick=mouse` 是**写死的文案**，真实值看 `Mouse stick: left|right`。
- `mouse_stick=left` 只是改写 SDL 数据库映射里的轴名，前提是设备在库里有映射行；两个设备都没有 → 无效。
- 往 `PortMaster/gamecontrollerdb.txt` 手工加映射行只能救一半，还会和桥抢输入 → 已还原（备份 `.bak.treeos`）。
- 桥的文件：`10_掌机游戏工程/tools/stickmouse.py` + `treeos-stickmouse.service`（故意不设开机自启，由 Flash 启动器拉起）。
- 部署：`/usr/local/bin/stickmouse.py`、`/etc/systemd/system/treeos-stickmouse.service`，手动 `systemctl start treeos-stickmouse`。
- 注意：`pkill -f stickmouse.py` 清理残留；别用 `pgrep -x`（进程名 15 字符截断）。

### D11 摇杆修复实录（2026-11-15，别再踩）

| 项 | 值 |
|---|---|
| 内核选项 | `CONFIG_INPUT_JOYSTICK=y` **和** `CONFIG_JOYSTICK_ADC=y`（缺父项则子项被静默丢弃） |
| 输入设备 | `adc-joystick`，`/dev/input/event0`，`EV=9`（只有 ABS 轴，**没有按键**） |
| 按键设备 | `gpio-keys`（A/B/X/Y/方向/Start/Select），两个设备分工 |
| 轴上限 | DT `abs-range = <180 800>`，中心实测 510–525，回中无漂移 |
| SDL 轴号 | axis 0 = ABS_X（左右），axis 1 = ABS_Y（上下）。**上下方向是反的**，配置里 up 要 `value="1"` |
| ES 写法 | `type="axis"`，`id` = SDL 轴号，`value` = ±1。**不要**写 `deviceNbAxes` 等属性（这版 ES 不读） |
| 双设备合并 | ES 会把两个 inputConfig 合并生效，按键和摇杆可共存，不用二选一 |
| 设备 GUID | `adc-joystick` = `190011526164632d6a6f797374696300`；`gpio-keys` = `1900bb07010000000100000000010000` |

### 修复方向

- **D8**：内核加 `CONFIG_CHARGER_RK817` + `CONFIG_BATTERY_*`，DT 里补 `rockchip,rk817-battery` / `rockchip,rk817-charger` 节点，让 `/sys/class/power_supply/battery/capacity` 出现。
- **D9**：两种做法——(a) 用 ALSA 的 `Master`↔`Playback` 别名（需确认 ES 读取方式）；(b) 小脚本把 Master 值写到一个 ES 读的文件/伪控件；先查 ES 是用 amixer 还是直接 ALSA API。
- **D10**：抓 ES 启动日志（LogLevel=debug）看它读的到底是哪个路径/什么格式。

> 这三条不影响游戏，但属于"第一眼体验"，应排在配网/主题之前修。
