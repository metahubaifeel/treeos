> 本文只记**怎么踩过去的**，结论性的方案见 `05_系统基线方案.md`。

## 踩坑清单（按踩到的顺序）

### 1. 面板不是"拷过来就能用"

厂商 dtb 写的是 `compatible = "simple-panel-dsi"` + `panel-init-sequence`，
但 mainline 的 `panel-simple.c` **根本不认这个 compatible**，也不解析 init-sequence。
→ 必须写驱动（`dts/panel-r36s.c`，151 条命令从 dtb 自动解出）。

### 2. DSI PHY 驱动是 `=m`，而我们是无 initramfs 启动 ⭐ 卡了最久

现象：`dw-mipi-dsi-rockchip ff450000.dsi: failed to get mipi dphy: -517`，
背光不亮、屏幕全黑，但系统其他部分都正常。

原因：`CONFIG_PHY_ROCKCHIP_INNO_DSIDPHY=m`，模块在 4.4 的 `/lib/modules` 里找不到，
DSI 控制器永远等不到 PHY → EPROBE_DEFER 死循环 → 面板驱动根本没机会 probe。

**教训**：无 initramfs 启动的机器，**所有显示链路驱动必须 `=y`**。

### 3. exFAT 没编进内核 → systemd 无限进应急模式 ⭐ 第二久

现象：屏幕反复刷
```
You are in emergency mode. After logging in, type "journalctl -xb" ...
Press Enter for maintenance (or press Control-D to continue):
```

原因：`/etc/fstab` 里 `/roms` 是 **exfat**，内核没开 `CONFIG_EXFAT_FS`，
挂载失败 → `local-fs.target` 失败 → 应急模式。

**教训**：换内核前先把 `fstab` 里所有 `fstype` 对一遍 `=y`。

### 4. 面板复位脚极性抄反了 ⭐ 症状最有欺骗性

现象：**背光亮、屏幕纯黑、什么画面都没有**。所有软件日志都正常（probe/prepare/enable 全过）。

证据在厂商自己的内核日志里：
```
panel-simple-dsi: reset-pin gpio = 112, active = 0
```
`active = 0` = **高电平有效**，而厂商 dtb 里写的是 `GPIO_ACTIVE_LOW`。

抄 dtb 时直接照搬 flags 就反了——驱动初始化时把复位脚拉低，**等于一直按着复位键**，
初始化命令发出去了，但面板在复位状态里听不见。

**教训**：`reset-gpios` 的 flags 不能只信 dtb，要看厂商内核日志里打印的 `active = ?`。

### 5. dtsi 里的 rotation 是给别的机器的

`rk3326-odroid-go.dtsi` 给 go3 的面板设了 `rotation = <270>`。
R36S 是原生 640×480 横向，不覆盖的话画面方向全错。

### 6. mainline 把 `MIPI_DSI_MODE_EOT_PACKET` 改名成了语义相反的 `NO_EOT_PACKET`

厂商 4.4 头文件：bit9 = 发 EOT。
mainline：bit9 = **禁** EOT。
照抄厂商的 `dsi,flags = 0x0a03` 会得到相反效果。正确做法是不置这一位（默认就发 EOT）。

### 7. `mipi_dsi_dcs_write_seq` 宏里有 `return ret`

所以调用它的初始化函数必须返回 `int`，写成 `void` 会报 151 条级联错误。

### 8. 引脚被重复申请

`gpio-keys-vol` 单独申请了一组 `btn-pins-vol`，而那些引脚已经被 `btn-pins` 配成 GPIO 了：
```
rockchip-pinctrl: error -EINVAL: could not request pin 64 (gpio2-0)
```
→ 音量键那组不要再单独申请 pinctrl。

### 9. 没有串口时怎么观测

这台机器没有可用的调试串口，屏幕就是唯一的观测点。两个保命技巧：

**a) 心跳灯**：厂商 LED 在 `GPIO2_B5`，加个 `gpio-leds` + `heartbeat` 触发器。
灯在闪 = 内核活着；不闪 = 内核没跑起来。**不依赖屏幕、不依赖网络**。

**b) `init=` 抓日志**：bootargs 加 `init=/usr/local/bin/treeos-diag-init.sh`，
内核一挂上 rootfs 就把 dmesg 写到 BOOT 分区（FAT32，电脑直接可读），然后再 `exec /lib/systemd/systemd`。
比 systemd 服务可靠得多——**系统卡在 multi-user 之前时，服务根本不会启动**。

### 10. `console=/dev/ttyFIQ0` 在 mainline 不存在

厂商用 fiq-debugger，mainline 没有这个设备。换 `console=tty0`。

### 11. 无 initramfs 启动要 `booti Image - dtb`

厂商原版 boot.ini 会加载 13 MB 的 `uInitrd`，那是 4.4 的 initramfs，配 6.12 会炸。
测试阶段直接 `booti ${loadaddr} - ${dtb_loadaddr}`（`-` 表示没有 initrd）。

### 12. zram 服务失败（待修）

`Failed to start zram swap for 1GB handhelds` → 内核没开 `CONFIG_ZRAM`。
1 GB 内存机器上这个是保命的，下一版补上。

### 13. 声卡还在 deferred probe（待修）

```
platform rk817-sound: deferred probe pending: asoc-simple-card: parse error
```
不影响显示和启动，下一轮再看。

### 14. 内置 Image 46 MB，厂商 u-boot 能正常加载

之前怀疑过加载上限（担心 32 MB 限制），实测 46 MB 正常加载，不是问题。
不过后面还是应该裁到 20 MB 左右（发行版镜像要省空间）。

---

## 调试手法总结（下次照做）

1. 先加**心跳灯**——立刻分清"内核没起来"还是"显示没起来"
2. 用 `init=` 抓日志到 FAT 分区——不依赖 systemd、不依赖网络
3. 一次只改**一个变量**，每轮都对比上一次的日志
4. 厂商 dtb 里的数值可以抄，但**极性/标志位要对照厂商内核日志验证**
5. 换内核前，先把 rootfs 的 `fstab`、模块依赖、`=y/=m` 全部对一遍

# 第二阶段：Debian 用户态 + 6.12 内核 + 菜单（2026-11-13 深夜）

## 结果

```
Linux treeos 6.12.0 #5 SMP PREEMPT aarch64
Debian GNU/Linux 13 (trixie)
OpenGL ES 3.1 Mesa 25.0.7（panfrost）
EmulationStation 跑在 kmsdrm + Mesa 上
```

内核、用户态、GPU 驱动、菜单**全部是自己的**，没有一个厂商闭源组件。

## 这一阶段的坑

### 15. debootstrap 不能直接装到 exFAT 上

`/roms` 是 exFAT，存不了属主/权限，解包直接失败。
→ 在 exFAT 里放一个 ext4 **镜像文件**，loop 挂载后往里装；装完直接 dd 到 p2。

### 16. 镜像不能放在同一张卡上还全卸载

安装脚本为了安全卸载整张卡的分区——可镜像就放在 `/roms` 里，一卸文件就没了。
→ 只卸载目标分区。

### 17. ES 依赖的旧库要"隔离"，不能盖住系统库

ES 是 2019 年编的，需要 `libjpeg.so.8`、`libtiff.so.5` 这类老版本号库。
但把整个依赖闭包塞进 `LD_LIBRARY_PATH` 会**盖住系统的 libwayland / libdrm**，导致：
- `libdecor: undefined symbol: wl_proxy_marshal_flags`
- `libdrm_amdgpu: undefined symbol: drmCloseBufferHandle`

→ 规则：**凡 Debian 自己有同名 SONAME 的，一律让位给系统**；只保留系统根本没有的老版本号库。判断要用真实文件路径，不能用 `ldconfig -p`（它会把 compat 目录也算成系统路径）。

### 18. 厂商 libMali 和内核驱动版本必须匹配

`/dev/mali0 is not of a compatible version (user 10.6, kernel 11.7)`。
同一个目录下有多个 mali 变体（`wayland-gbm` / `gbm`），只有一个能配上当前内核。
→ 用 `/usr/local/lib/aarch64-linux-gnu/` 那套（2021 年构建），并且注意 `libMali.so` 和 `libmali.so` **大小写是两个文件**。

### 19. ES 用的是桌面 OpenGL，不是 GLES

把 `libMali.so` 指到 Mesa 的 `libGLESv2.so.2` 会报 `undefined symbol: glMatrixMode`（固定管线函数）。
→ 指到 Mesa 的 `libGL.so.1`（桌面 GL）。

### 20. 换内核后输入设备名变了

ArkOS 用厂商私有 `odroidgo3-joypad` 驱动；mainline 是 `gpio-keys` + `adc-joystick`。
ES 的 `es_input.cfg` 对不上设备名 → 首次启动重新配置手柄。

### 21. ES 的主题字体要真 TTF

`Cabin-Bold.ttf` 等字体文件缺失时 ES 退回内置字体，中文缺字。
把字体换成 `.ttc` 也可能不认——要用 `.ttf`（`fonts-droid-fallback` 的 `DroidSansFallbackFull.ttf`）。

### 22. 品牌字符串在 ES 二进制里

`ARKOS4CLONE SETTINGS` 和版本号是硬编码的，做**等长替换**即可（`TreeOS SETTINGS` / `0.1 TreeOS`）。

### 23. I2S 驱动被 olddefconfig 丢掉

`SND_SOC_ROCKCHIP` 依赖 `SND_SOC`，单独 enable 会被重置。
→ 要一起打开 `SND_SOC_ROCKCHIP_I2S`、`SND_SOC_RK817`、`SND_SIMPLE_CARD`，并用 `System.map` 里有没有 `rockchip_i2s` 符号来验证。

### 24. ES 的视频播放依赖 VLC 插件目录

现象：屏保选"随机视频"后**全屏黑**，按任意键回菜单、马上又黑。
原因：ES 用 libvlc 播视频，我们只搬了 `libvlc.so.5`，**没搬 `/usr/lib/aarch64-linux-gnu/vlc/plugins`（12 MB）**。
→ 有引擎没有解码器，只能黑屏。从原 ArkOS 卡把 `vlc/` 整个搬过去，并设 `VLC_PLUGIN_PATH`。

### 25. ES 里 ScreenSaverTime 单位是秒，0 = 关闭

设 300/600 都会被立刻触发（这个 fork 的行为），最后**先用 0 关掉**，等视频问题解决再开。

### 26. R2 键在本机不发事件

`evtest` 能看到 313 支持，但实际按下无事件。亮度最终定案：**Select + 音量加/减**，
并且守护进程要处理 `value == 2`（长按连发），否则按一下动一档。

### 27. ArkOS 的按键守护不能直接搬

`oga_events.py` 依赖厂商私有手柄驱动（`arkos_joypad.active_keys()`），
主线内核下设备名和 API 全变了。→ 自己写 `treeos-keys.py`，直接读 evdev。

### 28. 更正：zram 内建并没有卡死启动

之前判断"加上 zram 就开不了机"是**错的**。后台验证结果：内核 6.12.0 正常起来了，
只是**WiFi 关联慢了几分钟**，人以为死机就关机了。

真正的问题在用户态：`zram` 设备没出现是因为系统里**没装 zram 配置**（`zram-tools` 缺），
不是内核的问题。

→ 最终方案改为 **zram 作为模块（=m）**：内核不动，模块热加载，起不来也不会影响开机。

### 29. 构建目录残留会导致模块编译失败

从 `ZSMALLOC=y` 改成 `=m` 后直接 `make modules` 报：

```
ERROR: modpost: mm/zsmalloc: 'zs_alloc' exported twice. Previous export was in vmlinux
```

原因是旧的 `vmlinux`/`Module.symvers` 里还留着内建版本。
→ 先 `make clean` 再编。

### 30. RTL8188EU 会掉线，且 NetworkManager 不自动重连

现象：机器开着、屏幕仍显示 `wlan0 192.168.100.186`，但外部 ping/SSH 全部不通。
`ip neigh` 里该地址是 `INCOMPLETE`。

原因：无线关联已经断了，但 NetworkManager 记着旧地址、界面照旧显示。
主线的 `rtl8xxxu` 驱动在弱信号/省电策略下容易掉线。

**处理**（待验证）：
- `/etc/NetworkManager/conf.d/` 里关掉 wifi 省电（`wifi.powersave = 2`）
- 配一个连接守护（定期 ping 网关，失败就 `nmcli con up`）
- 长期方案：换用 `rtl8188eu` 的 DKMS 驱动

**教训**：屏幕上的 IP ≠ 网络可用。判断设备是否在线，以从外部能否连通为准。

### 31. zram 最终方案（已跑通）

```
zram.ko + zsmalloc.ko（模块，vermagic 6.12.0 SMP preempt）
→ 拷进 /lib/modules/6.12.0/
→ depmod -a 6.12.0
→ modprobe zram
→ zramswap.service（zram-tools 自带，已 enabled）
```

实测：
```
/dev/zram0 partition 477.8M PRIO 100
comp_algorithm = lzo-rle（默认 lz4 内核没编，必须改）
```

**坑**：`init=` 钩子运行时 `/roms` 还没挂载，模块拷不进来。
钩子里要先 `mount -t exfat /dev/mmcblk0p3 /mnt/roms`。

### 32. 声音修复（2026-11-14，已出声）

三个问题叠加，缺一不可：

1. **rk817-codec 是 MFD 子设备，没有设备树节点**
   `drivers/mfd/rk8xx-core.c` 的 cell 只有名字，没有 `of_compatible`，
   导致 ASoC 组件无法与 DT 里的 codec 节点匹配 → `simple-audio-card: parse error`。
   → 打 5 行补丁：`{ .name = "rk817-codec", .of_compatible = "rockchip,rk817-codec" }`，
     DT 的 codec 子节点加 `compatible` 和 `#sound-dai-cells`。

2. **I2S（CPU 侧）驱动是模块，但没装**
   `CONFIG_SND_SOC_ROCKCHIP_I2S=m`，`/lib/modules` 里没有它 → ASoC 里只有 codec，
   没有 `ff070000.i2s` 组件。
   → 编成模块装进 `/lib/modules/6.12.0/`，写 `/etc/modules-load.d/treeos-audio.conf` 自动加载。

3. **路由名与驱动 DAPM 引脚不一致**
   厂商 DT 用 `MIC_IN` / `Headphone Jack`，mainline 驱动是 `MICL` / `HPOL` / `HPOR` / `SPKO`。
   → 改成驱动认识的命名。

**结果**：`card 0: rockchip,rk817-codec`，默认音量 85%，插耳机自动切走外放。
**注意**：手动 `unbind/bind` 声卡会在 `snd_soc_register_card` 处触发 oops，别这么测试，直接冷启动。

## 踩坑 #33：不加载交叉编译环境就跑 olddefconfig，会**静默重写成 x86 配置**（2026-11-15）

**现象**：只加了一个 `CONFIG_INPUT_UINPUT`，`make -j16 Image` 成功，Image 从 48 MB 缩到 25 MB，
刷进去黑屏开不了机。

**原因**：
```bash
./scripts/config --enable INPUT_UINPUT
make olddefconfig        # ← 没 source env.sh，ARCH 默认成主机 x86_64
make -j16 Image
```

第一次 `olddefconfig` 在 x86 主机环境下重新生成配置，**ARM64 / ARCH_ROCKCHIP / 所有 Rockchip 驱动全部被丢掉**；
后面虽然用 aarch64 工具链编译成功，但编出来的内核根本没有需要的驱动。

**恢复方法**：
```bash
# 从能开机的 Image 里抽回当时的内核配置（前提：CONFIG_IKCONFIG=y）
./scripts/extract-ikconfig /boot/Image.prev2 > /tmp/working.config
cp /tmp/working.config .config
source ../env.sh                  # ← 必须
./scripts/config --enable INPUT_UINPUT
make olddefconfig
make -j16 Image
```

**判断标准**：编译完看 `arch/arm64/boot/Image` 大小，本机正常在 **48 MB 左右**；
掉到 25 MB 就说明配置坏了，不要刷。

**教训**：改动内核配置前先 `source env.sh`；改完存一份 `.config` 到仓库（`kernel/config-6.12-r36s`），
不要只靠工作区里的 `.config`。
