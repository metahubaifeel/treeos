# 硬件改造的软件接口

> 2026-11-13　依据：大佬（硬件）口述的改造清单 + 我们自己的 dtb 实测
> 用途：**给做 TreeOS 的那个 session 当输入，也给大佬对接口用。**
> **2026-11-13 更新：大佬已答复（快充 9V/12V、无信号脚、只读输入电压）。代码已确认 `dc_det` 不能判“充电中”、内核本来就在做库仑计、PMIC 有未导出的 USB_VOL ADC。执行方案见 `07_硬件改造软件方案.md`。**

## 一、总表：他改的东西，哪些要软件

| # | 改造项 | 要不要软件 | 现在有没有 | 谁做 |
|---|---|---|---|---|
| 1 | **充电检测**（5V→分压→3.3V→检测到正在充电） | ✅ 要 | ❌ `dc_det` 只改充电参数，**不能判“充电中”**（代码已确认） | 改走 PMIC USB_VOL |
| 2 | **输入电压检测**（分压 + 滤波电容 → ADC） | ✅ 要 | 🟡 **RK817 有 USB_VOL ADC（0x7E/0x7F）**，驱动已采样未导出；SARADC ch0 更像电池电压 | 先确认落点 |
| 3 | **高压快充提示**（9V/12V → 提示快充） | ✅ 要 | ❌ 要新做 | TreeOS |
| 4 | **库仑计**（电压×电流×时间 → 准电量） | ✅ 要 | 🟢 **PMIC 自带电量计 `rk817_fg`**，电流电压都能读 | TreeOS |
| 5 | **PWM 风扇调速** | ✅ 要 | ✅ **GPIO32/33/36/41 已验证可用** | TreeOS |
| 6 | 加两个 USB 口 | 🟡 **要（双人手柄）** | ✅ 内置 hub 空 2 路，大佬已做好 | TreeOS |
| 7 | 更大电流的 5V 电源 | ❌ 不要 | — | 纯硬件 |
| 8 | 天线 / 功放改 5V 供电 | ❌ 不要 | — | 纯硬件 |

**结论：6 项要软件（原 5 项 + 双人手柄）。电源 3 项底层已备好，真正要新写的是「快充提示」「风扇调速」「双人手柄」。**

## 二、逐项说清楚

### 1 · 充电检测

**大佬说**：电阻分压 0~3.3V，接 5V 时分出 3.3V，单片机检测到就提示"正在充电"。他外接 3.3V 测试过，功能正常。

**我们这边的情况**：设备树里 **PMIC 本来就有充电检测**：

```
charger:  dc_det_gpio = <gpio0 11>
```

系统里也能看到：

```
gpio-11  (rk817_dc_det)  in  lo
```

**所以要问他的第一件事：**

> 你那个充电检测信号，是接到 DC 口分压后进 ADC，还是拉一根 GPIO？
> 如果是 GPIO，接的是哪个脚？能不能直接并到现有的 `dc_det`（GPIO0_11）上？

**已查 vendor 4.4 驱动：不能。** `rk817_charge_dc_det_worker()` 只调用 `set_chrg_param()` 和 OTG 切换，**不设置** `ac_in` / `dc_in`；`ac` 的 `ONLINE` 由 USB PHY/extcon 报。所以给 `dc_det` 3.3V 只会改充电参数，不会让系统显示“正在充电”。**不要把这根线当插电判断。**

### 2 · 输入电压检测（ADC）

**大佬说**：分压之后出一个电压，有滤波电容对地，推测是接 ADC 的。改分压值就能读出输入电压。

**我们这边**：**SARADC 已经启用了**：

```
/saradc@ff288000  status = okay   (rockchip,px30-saradc)
#io-channel-cells = 1
```

**所以要问他的第二件事：**

> 你把分压后的信号接到哪个 ADC 通道？（RK3326 的 SARADC 只有 2 个通道，得定死一个）

**代码已查：RK817 PMIC 自己就有 USB_VOL ADC**（reg 0x7E/0x7F），vendor 驱动每 5 秒采一次存进 `voltage_usb`，但**没有导出到 sysfs**。SoC SARADC ch0 实测 0.29V ≈ 电池/12.8，更像电池电压采样。所以优先确认分压是不是接 PMIC USB_VOL；是的话，软件打个小补丁把 `voltage_usb` 暴露出来即可。

### 3 · 高压快充提示

**大佬的设想**：改分压值后能读出输入电压，5V 就是普通充电，9V/12V 提示高压快充。

**软件要做**：

- 定时读 ADC 通道
- 按电压分段：`<5.5V` 普通 / `5.5~9.5V` 快充 / `>9.5V` 高压快充
- 结果交给 EmulationStation 的状态栏显示

**要问的第三件事：**

> 判定逻辑放在系统这边（读 ADC 自己算），还是你模块那边给一个"快充中"的信号脚？
> 前者软件全包，后者硬件更省事，但要多占一根 GPIO。

### 4 · 库仑计（这个有好消息）

**大佬说**：有了电压和电流，可以用电压×电流×时间算出充放电容量，像库仑计一样，电量就准了。

**好消息：这颗 PMIC 自带电量计（fuel gauge），不用等硬件。**

```
battery:  compatible = rk817,battery  rk817_fg
          design_capacity / ocv_table / bat_res / sample_res  ← 全是电量计的参数
```

系统里已经在暴露这些值（实测读数）：

```
POWER_SUPPLY_STATUS      = Discharging
POWER_SUPPLY_VOLTAGE_NOW = 3825000     (3.825 V)
POWER_SUPPLY_CURRENT_NOW = -621000     (-621 mA，负=放电)
POWER_SUPPLY_CAPACITY    = 87          (%)
```

**代码已确认：内核本来就在做库仑计。** vendor `rk817_battery.c` 的 `rsoc` 来自 `Q_PRESS` 寄存器 ÷ FCC；`ocv_table` 只用于首次上电/长时间断电校准。`CHARGE_COUNTER` 是充电次数，不是容量。所以用户态**不要重复积分**；要做的是校准 `design_capacity`（DTS 3380 vs 电芯 3000mAh）和显示速率/剩余时间。

**这件事跟他的硬件改造不冲突，可以先做。** 他改的电流检测电路可以让读数更准，但不是必需的。

### 5 · PWM 风扇调速

**大佬说**：需要软件，否则风扇全速。

**我们这边已经实测过了**：未焊 flash 焊位上的四个脚可以自由控制。

```
GPIO32 / GPIO33 / GPIO36 / GPIO41
export 成功，设 out、写 1 读 1、写 0 读 0 全部正常，无驱动占用
```

**要问的第四件事：**

> 风扇接哪一个？（四个里挑一个，建议 **GPIO32**，它是列表第一个）
> 中间加 MOS 管了吧？（GPIO 带不动 30~50mA）

**软件侧要做**：

- 读温度 `/sys/class/thermal/thermal_zone0/temp`
- 按温度算占空比
- 用软件 PWM 驱动那个脚（几百 Hz 够用，风扇有惯性）

### 6 · 两个外置 USB 口（要软件：双人手柄）

大佬已经把内置 hub 空着的两路拉出来了。系统会把它当普通 USB HID，但 **Player 1/2 映射、热插拔、RetroArch/ES 手柄配置**要软件做。详见 `07_硬件改造软件方案.md` §3.6。

### 7~8 · 纯硬件，软件不用管

| 项 | 为什么不用软件 |
|---|---|
| 更大电流的 5V 电源 | 只是供电能力变强，接口不变 |
| 天线 / 功放改 5V 供电 | 声音更响、干扰更少，但音频通路不变 |

**注意一条**：功放 5V 改造后，大佬明确他在功放上自己调增益，**软件不动音量刻度**。

## 三、给大佬的问题清单（直接发）

> 1. **输入电压**：分压 + 电容那路到底接 RK817 的 USB_VOL（0x7E/0x7F）还是 SoC SARADC？R1–R5 阻值是多少？
> 2. **快充**：9V/12V 最终进线性充电（TP4056/ME4057）吗？还是换开关型 + 路径管理？

> 5. **电流采样**：采样电阻实际值是多少？DTS 里配的是 10mΩ。
>
