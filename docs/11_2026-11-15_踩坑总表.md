## 一、输入架构：为什么 R36S 这么难搞

### 1.1 硬件事实

| 设备 | event 节点 | 内容 |
|---|---|---|
| `adc-joystick` | `/dev/input/event0` | 只有 ABS_X/Y/RX/RY，**没有任何按键** |
| `gpio-keys` | `/dev/input/event1` | 只有按键，17 个键码 |
| `gpio-keys-vol` | `/dev/input/event2` | 音量键（KEY_VOLUMEDOWN=114 / UP=115） |

摇杆走 **ADC**（经 io-channel-mux），按键走 **GPIO**——原厂就是这样拆的。

### 1.2 gpio-keys 实测键码（2026-11-15 抓包确认）

```
A=305  B=304  X=307  Y=308
L1=310 R1=311
上=544 下=545 左=546 右=547
Select=704  Start=705
L3=706  R3=707
FN=708
```

**注意**：之前用脚本读 `/sys/class/input/*/capabilities/key` 解码得到过一组乱七八糟的码
（0,1,2,3,4,224...），那是解码方式错了。**唯一可信的方法是让用户按键、直接抓 event 流。**

### 1.3 SDL / RetroArch 不合并设备

SDL 不会把两个物理设备合成一个 GameController；ES 能同时用是因为 ES 自己合并了
所有 inputConfig。RetroArch 只能选一个设备当 Player 1，所以"按键和摇杆必须二选一"。
**这是所有映射问题的根源。**

### 1.4 别的系统怎么解决的（调研结论）

- ROCKNIX / Arch-R：在**内核里写专用 joypad 驱动**（`rocknix-joypad`），把 ADC 和 GPIO
  合成一个输入设备，然后靠 RetroArch autoconfig 配置。
- 我们（用户态）：写 `padmerge.py`，用 uinput 造虚拟设备合并两者。

## 二、RetroArch 替换：ArkOS 魔改版不能用

### 2.1 症状链

1. GBA 游戏黑屏但进程活着 → 日志 `c_RkRgaBlit failed` 刷屏
2. 换核心（gpsp_ezode_mod → gpsp）**仍然黑** → 说明问题不在核心
3. `--verbose` 发现 GL 上下文正常：`Mesa / Mali-G31 (Panfrost)`，`OpenGL ES 3.1`
4. 结论：**ArkOS 的 RetroArch 本体链接了 `librga.so.2`，每帧用 RGA 拷画面**，
   主线内核没有 RGA 驱动 → 黑屏

### 2.2 换 Debian 官方 RetroArch

```bash
apt install retroarch   # trixie 源 1.20.0
```

启动器 `/usr/local/bin/retroarch` 改成一行 exec `/usr/bin/retroarch`，
旧版备份 `retroarch.arkos`。

### 2.3 第二个坑：兼容库把系统库顶掉

换完标准 RA 后游戏**闪退**（黑一下、左上角光标、回列表）。journal 真因：

```
/usr/bin/retroarch: symbol lookup error: libavutil.so.59: undefined symbol: vaMapBuffer2
```

`treeos-es.sh` 里设了 `LD_LIBRARY_PATH=/opt/treeos-compat/lib`，里面的旧 `libva.so.2`
覆盖了系统新库。**启动器里 `unset LD_LIBRARY_PATH` 解决。**

### 2.4 验证数据

标准 RA + gpsp：10 秒推 359 帧（≈36fps），零 RGA 报错。

## 三、按键映射：为什么改了十几次都不对

### 3.1 关键教训

- `es_input.cfg` 里的 `code=` **不是**内核键码，是 SDL 的 button index——别混用。
- RetroArch 的按钮索引顺序**不等于**内核键码排序，也不等于 SVN 里的直觉顺序。
- 每次靠"推理"改索引都错，最后靠**让用户按键抓 event** + 观察行为反推才对上。

### 3.2 最终方案：键盘映射（推荐，已采用）

不再造虚拟手柄，padmerge 造**虚拟键盘**，把按键翻译成键盘键：

| 实体 | 键盘 |
|---|---|
| A / B / X / Y | X / Z / A / S |
| L1 / R1 | Q / W |
| Select / Start | RShift / Enter |
| L3 / R3 | 1 / 2 |
| FN | F1 |
| 方向键 + 摇杆 | Up/Down/Left/Right |

RetroArch 侧用明确无歧义的键盘绑定：

```ini
input_player1_a = "x"
input_player1_b = "z"
input_player1_x = "a"
input_player1_y = "s"
input_player1_l = "q"
input_player1_r = "w"
input_player1_select = "rshift"
input_player1_start = "enter"
input_menu_toggle = "f1"
input_joypad_driver = "null"
```

`input_joypad_driver = "null"` 还顺手消掉了 `gpio-keys is not configured` 的 OSD 提示。

### 3.3 uinput 的两个硬坑

1. **`UI_ABS_SETUP` 结构体顺序**：内核要求 `__u16 code` 在前、`struct input_absinfo` 在后
   （共 28 字节）。写成 absinfo 在前会报 `OSError: [Errno 34]`。
   ```python
   struct.pack("<HH6i", code, 0, value, min, max, fuzz, flat, resolution)
   ```
2. **轴量程**：`adc-joystick` 的 DT 写 `abs-range = <180 800>`，但实测原始值能到
   `40..916`（甚至 0..1023）。虚拟设备必须声明 **0..1023**，否则超范围被截断。

### 3.4 摇杆方向

实测需要 `INVERT_X = True, INVERT_Y = True`（padmerge 里两个常量）。
摇杆直译成方向键的做法（在 padmerge 里做）比依赖 RA 的 `analog_dpad_mode` 稳得多。

## 四、存档被清空（最痛的一条）

### 4.1 发生了什么

- `/roms/gba/洛克王国：集结.srm` 从 131072 字节真实数据 → 0 字节 → 全 0xFF（空 flash）
- 原因链：
  1. ArkOS 时代开了 `sort_savefiles_enable=true`，存档被放进 `gpSP/` 子目录
  2. 根目录那份变成空白，游戏启动时读到空存档
  3. RetroArch 退出时把内存里的空 SRAM 写回根目录 `.srm`，覆盖
  4. 我们第一次"恢复"时从 `gpSP/` 拷回来，那份其实也已经是空白的

### 4.2 恢复方法（已验证）

电脑上的原始备份：
```
.backup/EASYROMS-rk3566-20261114/gba/洛克王国：集结.srm   # 111386 字节有效数据
```
用 `scp` 拷回去即可。验证是否为空存档：
```bash
tr -d '\377' < file.srm | wc -c    # 结果 0 = 全是 0xFF = 空
```

### 4.3 防止再发生

- 已设 `sort_savefiles_enable=false`、`sort_savestates_enable=false`
- `savefiles_in_content_dir=true`（存档跟 ROM 同目录）
- **重要：用户自己的 ROM/存档，动之前先备份到电脑**

## 五、RetroArch 中文显示

### 5.1 三个坑叠在一起

1. ArkOS 配置里 `xmb_font = "~/Cabin-Bold.ttf"` —— 这个字体没有中文
2. **RA 的字体目录是 `~/.config/retroarch/assets`**（`assets_directory` 配置项），
   不是 `/usr/share/libretro/assets`。改错目录 = 永远没效果
3. Ozone 界面**不支持 `menu_scale_factor`** 缩放；只有 XMB 支持

### 5.2 解法

```bash
# 真正的字体位置
~/.config/retroarch/assets/ozone/regular.ttf
~/.config/retroarch/assets/ozone/bold.ttf
~/.config/retroarch/assets/xmb/monochrome/font.ttf
# 全部替换为文泉驿微米黑（原文件备份 .bak）
```

启动器**不要**再强制 `menu_driver`，否则用户在设置里切换界面永远无效
（本次踩过：强制 ozone 导致改 xmb 不生效）。

## 八、中文名 zip 的坑（2026-11-15 晚）

**现象**：GBA 列表里 `口袋妖怪 绿宝石.zip` 打不开，黑一下回菜单。

**日志**：
```
[Content]: Core requires uncompressed content - extracting archive to temporary directory.
[ERROR] [Content]: 从压缩包中解压游戏失败: "/roms/gba/口袋妖怪 绿宝石.zip#�ڴ����� �̱�ʯ.gba"
```

**原因**：zip 内文件名是 **GBK 编码**（Windows 中文压缩），RetroArch 按 UTF-8 解析失败。

**解法**：
1. 用 Python 解压，非 UTF-8 标记时 `cp437 -> gbk` 还原文件名（脚本 `/tmp/unzip_roms.py`）
2. **原始 zip 移出扫描目录**（`/roms/_zips/gba/`），否则 ES 会把 zip 和 gba 都列出来，
   同一游戏出现两份，用户不知道选哪个

**教训**：处理 ROM 集合时先想"会不会重复列出""编码是否兼容"，不要等用户发现问题。

## 九、2026-11-19 Flash 设置界面：绑定/多键/图标

### 9.1 B 键既当“返回”又当“要绑定的键”

**现象**：用户在鼠标右键行按 A 进入绑定，想绑 B，一按 B 就退出绑定。
**原因**：把 B 设计成“轻点取消”，和候选键重叠。
**解法**：绑定页整屏独立；页内所有手柄键只作候选，不再兼职返回/取消。
取消改为 FN 或 START+SELECT 同时按。

### 9.2 一个手柄键只能存一个 vk

**现象**：A 映射了 J 就不能同时要空格；profile 里 `south=74` 是单值。
**原因**：数据模型是 `int vk`。
**解法**：改成 `vks[6]` 列表；profile 写 `south=74,32`；padinput 按下时逐个发、松开逐个收；
键盘页 A 短按切换、长按移除；只写用户改过的行（`maps_touched`），避免把模板默认值写死。

### 9.3 保存时把模板默认值写成显式键

**现象**：用户只设了鼠标键，保存后 A 却开始发 J（模板默认），和点击叠加。
**原因**：save_profile 会把所有未出现的 mapping 行补全。
**解法**：只补用户实际改过的行；flash-template 仅抑制“模板默认、用户未显式设置”的点击键键盘叠发。

### 9.4 flashcfg set 把 schema=3 档案插成重复 schema

**现象**：v3 档案被 `flashcfg set` 插入 `schema=2`，之后 `read_pairs` 报重复键，读到默认值。
**原因**：判断条件是“是否存在与常量完全相同的行”，常量还停在 2。
**解法**：`SCHEMA=3`；按“是否已有 schema= 行”判断；migrate 先剔除旧 schema 行再写新行。

### 9.5 设置界面退出后 Weston 卡在 GL 初始化

**现象**：保存返回游戏，Weston 日志停在 `Using GL renderer`，Wayland socket 不出，
Ruffle 报 `neither WAYLAND_DISPLAY ...`。
**原因**：mapper 的 kmsdrm/DRM master 释放与 Weston 抢设备之间没有缓冲。
**解法**：`flash-return2.sh` 重新编译 session 后 sleep 2 秒再 exec 启动器。

### 9.6 设置界面初始化失败也会把游戏拉起来

**现象**：DRM 被占用时 mapper 初始化失败，退出路径仍然 exec 回游戏，形成来回弹。
**解法**：只有真正初始化成功（`init_ok`）才回游戏；失败回 ES。

### 9.7 图标不要手画

**教训**：手画的圆/十字既慢又不像。用 Kenney Input Prompts（CC0）现成 PNG，
白色 ABXY 按实机配色染色，方向键/鼠标图标自带按下高亮；stb_image 解码，附 LICENSE。
