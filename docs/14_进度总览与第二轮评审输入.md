## 四、今天（11-15）新出现并解决的问题

1. ArkOS RetroArch 依赖 RGA → 主线黑屏 → 换 Debian 官方 1.20
2. 兼容库污染（旧 libva）→ 符号错误闪退 → unset LD_LIBRARY_PATH
3. 输入：按键/摇杆两个设备 → padmerge 虚拟键盘 + RA 键盘绑定
4. 存档被 RA 写空 → 关 sort_savefiles、从电脑备份恢复
5. RA 中文字体：真目录是 `~/.config/retroarch/assets`
6. ES 配置三层覆盖（sd1 模板 → /etc → 内存回写）
7. 内核 olddefconfig 不带 ARCH → 静默变 x86 配置（黑屏）

详见 `11_2026-11-15_踩坑总表.md`。

## 六、给第二轮评审的问题（请 GPT-6.x 重点回答）

1. **交付优先级**：在"能玩 GBA"的原型上，下一步最该证明什么？
   我们认为是：新卡刷 v3 → 开机 → 玩 GBA → 存档 → 关机，全程无电脑。
   是否同意？有没有更关键的先决条件？
2. **性能**：GBA 36fps 的排查顺序？（音频同步/线程视频/governor/KMS 刷新率/核心）
   有没有已知的 RK3326 + panfrost + RetroArch 1.20 基线数据？
3. **维护成本**：84 个 ArkOS 脚本要不要清理？清理的风险与收益？
   是否应逐步替换为 systemd 单元 + 少量 Python 工具？
4. **OTA 设计**：在 16GiB 整卡镜像（rootfs 分区 11GiB）的布局下，
   A/B rootfs 还是 recovery 分区更现实？断电恢复如何保证？
5. **1GB 内存**：zram 477MiB 是否应调大？swappiness 建议值？
   有没有 RK3326 上跑 N64/PSP 的可行基线？
6. **风险清单**：我们目前最可能"翻车"的地方是什么？
