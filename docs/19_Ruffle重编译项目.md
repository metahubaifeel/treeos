# Ruffle 重编译项目（暂停/菜单/返回游戏）

立项日期：2026-11-17
状态：立项，待启动

## 一、目标

让掌机上的 Flash 游戏具备 RetroArch 级体验：

1. 游戏内按 FN，**原地暂停**（不退出进程、不丢失进度）
2. 菜单半透明叠加在游戏画面上
3. 改完映射/摇杆模式后按 FN，**回到暂停前的位置继续玩**
4. 菜单期间音频暂停，关闭后不追帧、不卡键

## 二、为什么单独立项

今天的实测结论（见 `07_运行时架构与优化路线.md` 第二十六节）：

- LD_PRELOAD 替换 `SDL_GL_SwapWindow` / `SDL_RenderPresent` / `eglSwapBuffers` / `SDL_GL_GetProcAddress` **全部无效**
- 但 `SDL_Init` 能被拦截，证明 LD_PRELOAD 本身生效
- 结论：冻结核心的呈现路径在二进制内部，公开符号 hook 不到

因此「暂停 + 叠加菜单」必须改运行时本身，这不是配置或脚本能解决的。

## 三、技术路线

### 3.1 取匹配源码

```
C:\r36sc\git\checkouts\ruffle-b1b568dcb5621339\563854a\core\src\...
```

对应 Ruffle 提交 `b1b568dcb5621339`。第一步是从 GitHub 拉取该提交，并在本地比对二进制字符串特征，确认是同一版本。

如对不上，退回「与冻结核心行为等价的上游版本」，用兼容性测试兜底。

### 3.2 改动点

在 Ruffle 的每帧循环里加入菜单状态：

```rust
if menu_open {
    pump_menu_input();          // 读手柄，处理菜单导航
    audio.pause();
    render_last_frame_and_menu(); // 上一帧 + 半透明菜单
} else {
    player.tick(dt);            // 原有逻辑
    player.render();
}
present();
```

关键点：

- 暂停时保存 `Instant` 基准，恢复时重置，避免追赶时间
- 菜单期间不推进 `Player`
- 菜单绘制用现有渲染后端（wgpu/glow），不引入新依赖
- 输入：菜单期间消费手柄事件，退出时清空按键状态

### 3.3 构建环境

不在这台掌机上编译。用 5060 那台（一台 20 核 / 46GB 的构建机，docker）：

- 安装 rustup + `cargo install cross`
- 目标：`aarch64-unknown-linux-gnu`（掌机 glibc 2.41，Debian 13，满足）
- 依赖：SDL2、ALSA、udev 的 aarch64 版本（cross 镜像内装或 vendored）
- 产物：`ruffle-desktop` arm64 二进制，作为新的运行时核心

### 3.4 与 TreeOS 的边界

- 产物放 `/roms/ports/rufflehandheld/runtime/core/` 作为新核心
- 菜单 UI 由我们自己的代码提供，不依赖 ES
- 不改内核、不改 ES；纯用户态替换
- 回退：保留现有冻结核心，配置切换

## 五、风险

1. **源码对不上冻结核心**：行为差异、兼容性回退
2. **交叉编译依赖复杂**（SDL2/ALSA/udev）：可能需要 vendored 构建
3. **1 GB 内存**：新核心 + 菜单可能比冻结核心重，需要实测
4. **DRM 恢复**：即使自己做菜单，全屏切换仍需小心 KMS 状态
5. **维护成本**：核心更新后要重新打补丁

## 六、当前替代方案（保留）

在 M 系列完成前，掌机继续用现有方案：

- FN → 设置 UI（SDL2，键盘布局 + 三档摇杆）
- 保存后**重新加载游戏**（几秒）
- 退出用 Select+Start，音量键可用

这套已稳定，是项目的保底。
