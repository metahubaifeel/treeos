# 经典页游能不能离线跑：三类清单

更新：2026-11-18

不是所有 4399 游戏都是「一个 SWF 拿下来就能玩」。按运行依赖分三类，
每类的验证方法和承诺都不一样。

## 第一类：单文件 / 多文件离线 Flash

**能离线跑，前提是资源完整。**

- 典型：《黄金矿工》《魔塔》《死神 vs 火影》（2.x，资源齐全的版本）
- 形态：一个 SWF，或一个主 SWF + 同目录资源（图片、音频、数据文件）
- 验证：Ruffle 能加载、能进菜单/对战、输入可用、能存档
- 承诺：验证过的具体版本可以承诺「可玩」；同名的其他版本仍需单独测

## 第二类：依赖后端的在线页游

**前端能跑不等于游戏能玩。**

- 典型：《洛克王国》《赛尔号》这类需要登录、服务器下发的游戏
- 风险：账号体系、服务器协议、动态资源、跨域、版本更新
- 现实：客户端能打开，不代表能进游戏；Ruffle 不会替代原服务器
- 做法：只做「客户端能否加载、界面能否显示」的可行性记录；
  **不承诺可玩**，也不把这类作品作为销售卖点

## 第三类：根本不是 Flash

- 典型：Unity / H5 / 客户端安装包形态的游戏
- 结论：不在 Ruffle 的能力范围；不要混进 Flash 清单

## 测试记录模板

| 字段 | 说明 |
|---|---|
| 文件名 / 哈希 | 固定版本，避免同名不同版 |
| 类别 | 1 / 2 / 3 |
| 启动 | 黑屏 / 标题页 / 可操作 |
| 输入 | 鼠标、键盘、手柄各自是否可用 |
| 声音 | 有 / 无 / 异常 |
| 存档 | 退出重进是否保留 |
| 帧率 | 平均 FPS、明显卡顿点 |
| 结论 | 可玩 / 仅展示 / 不可用 |

## 承诺原则

- 对外只列「已按上表验证过」的具体版本；
- 第二类作品单独标注「需要服务器，未验证」；
- 任何时候都不写「所有 4399 游戏都能玩」。
