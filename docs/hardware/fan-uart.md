# 2026-11-15 · 风扇改为单片机 + UART

> 来源：硬件大佬 2026-11-15 语音转文字
> 影响：`07_硬件改造软件方案.md` §3.5 的风扇方案从「GPIO32 软件 PWM」改为「UART 风扇控制器」；
> GPIO32 软件 PWM 保留为**没有单片机时的降级方案**。

---

## 一、大佬的方案（要点）

- 风扇板上加一颗单片机，R36S 通过 **UART** 和它通信。
- **我们发给单片机**：频率 + PWM 百分比，约每 **300 ms** 一次。
- **单片机回传**：风扇转速 + 5V 主/辅助电源电压。
- 超时逻辑：
  - UART 模式下 **3 秒**收不到数据 → 输出 0% PWM；
  - 开机后**从没收到过** UART 数据 → 一直 100%（兼容没改软件的人）；
  - 收到过一次 → 进入 UART 模式，之后以串口数据为准；断线/没数据 → 回 0。
- 机器本身的调试 UART（GND/RX/TX/VCC 那组）不动，继续可用于调试。
- 他先把电路和单片机程序做完，再给我们通信格式；我们按他的格式读写。
- 他还要解决“没有 FG 转速输出”的风扇怎么测转速。

---

## 二、必须先解决的：SoC 这边的 UART 引脚

**RK3326 不是单片机，UART 是固定引脚，不能随便拿两个 GPIO 当 RX/TX。**

我们验证过的四个空闲脚 **GPIO32 / 33 / 36 / 41**（GPIO1_A0/A1/A4/B1）**都不是 UART 功能**。

按 RK3326/PX30 的引脚复用表，可选的 UART 对：

| UART | 引脚 | GPIO 编号 | 备注 |
|---|---|---|---|
| UART1（调试口） | GPIO1_C0 / C1 | 48 / 49 | **已被调试串口占用，不动** |
| UART2 M0 | GPIO1_D2 / D3 | **58 / 59** | 候选，需确认板上可焊点 |
| UART4 | GPIO1_D4 / D5 | **60 / 61** | 候选 |
| UART2 M1 | GPIO2_B4 / B6 | **76 / 78** | 候选，挨着指示灯（GPIO2_B5=77） |
| UART5 | GPIO3_A1 / A2 | **97 / 98** | 候选 |
| UART3 M1 | GPIO1_B6 / B7 | 46 / 47 | ❌ 已被十字键占用 |
| UART3 M0 | GPIO0_C0 / C1 | 16 / 17 | ❌ C0 是背光 PWM1 |
| UART0 | GPIO0_B2 / B3 | 10 / 11 | ❌ B3 是 dc_det，B2 是 PMIC 中断 |

**结论：需要在 UART2 M0 / UART4 / UART2 M1 / UART5 里选一对，确认板上有没有测试点/可焊盘。**

如果都不好接，最稳的替代方案：**在他板子上加 USB 转串口（CH340/CP2102），走内部 hub 的空口**；我们这边就是 `/dev/ttyUSB0`，完全不占 UART。代价是占一个内部 USB 口。

---

## 三、安全逻辑要改：超时回 0 有风险

大佬现在的设计：UART 模式 3 秒没数据 → 0% PWM。

**问题**：如果系统在运行、只是 `treeos-fan` 崩了或线断了，风扇会停，机器可能过热。

**建议**（他已经在量 5V 主电源，正好可以利用）：

```
5V 在 + 串口 3 秒没数据  → 100%（或按板上 NTC 自己跑）
5V 不在（整机关机）      → 0%
要主动关风扇             → 我们显式发 0%，不靠超时
```

这样既安全，也不会在关机后还转。普通模式（从没收到过数据）跑 100% 是对的。

---

## 四、通信协议（等他给格式，先列我们要问的）

他定格式，我们按他的来。需要确认：

1. 波特率（建议 115200 或 9600，8N1）；
2. 电平：3.3V？单片机 TX 不能是 5V，否则要电平转换；
3. 帧格式：帧头、长度、命令、序号、校验（CRC8/CRC16/累加和）、字节序；
4. 心跳/超时：300 ms 发送，3 s 超时；
5. 5V 电压的量程和分压比（回传单位是 mV 还是原始 ADC）；
6. 转速单位（RPM）和无效值（比如 0xFFFF = 无 FG）。

**我们发给它**：`频率(Hz)` + `占空比(0–10000 = 0.00–100.00%)`。
**它回传**：`转速(RPM)` + `5V 电压(mV)` + 状态位。

建议帧里带一个**序号**，方便判断丢帧/重连。

---

## 五、软件侧要做的

- `treeos-fan.service` 改为 **UART 版**：
  - 每 300 ms 发一帧（频率 + 占空比）；
  - 读回转速和 5V 电压，写进 `/run/treeos/fan.json`；
  - 串口打不开/断线 → 重连，并记日志；
  - 温度曲线不变，只是把「写 GPIO」换成「发 UART」。
- 降级：没有单片机/串口不存在 → 回到 GPIO32 软件 PWM（旧方案）。
- UI：ES/状态页显示风扇转速、5V 电压（后续接）。
- 开机顺序：先等串口就绪，再发第一帧；发不出去就降级。

## 八、2026-11-16 硬件合作方补充

- 风扇板用的是 **8 脚 SO8 单片机**，引脚大致是：
  - 1 MCLK/RST/P5.4
  - 2 VCC/AVCC/VREF+
  - 3 GND/AGND/VREF-
  - 4 P5.5
  - 5 P3.0/ADC8/RxD/INT4
  - 6 P3.1/ADC9/TxD
  - 7 P3.2/ADC10/INT0/SCL
  - 8 P3.3/ADC11/INT1
- 除了 RX / TX / PWM，还能多出两个引脚；带 ADC，可以测升压输出的 5V 电压。
- 硬件合作方提醒：**风扇 PWM 必须用硬件 PWM**，单片机靠定时器翻转 IO 做不到那么快的 PWM。所以 MCU 选型要带硬件 PWM。
- 合作方仍然认为 SoC 侧“随便两个 GPIO 配成 RX/TX”就行——**这里必须纠正：RK3326 的 UART 是固定引脚。**

**SoC 侧 UART 结论：**

1. **最稳：风扇板加 USB 转串口（CH340/CP2102）**，走内部 hub 的空口，SoC 看到 `/dev/ttyUSB0`。不占 UART、不动调试口，代价是占一个内部 USB 口。
2. **次选：用调试 UART1（GPIO1_C0/C1 = 48/49）接风扇**，调试改走 USB/ADB/SSH。“调试口不冲突”的说法其实不成立——用了就是冲突。
3. **另找 SoC UART**：UART2 M0（58/59）、UART4（60/61）、UART2 M1（76/78）、UART5（97/98），需要确认板上有测试点/可焊盘。

**回复时要补的两句：**

- “MCU 带硬件 PWM 没问题；但 SoC 这边不是随便两个 GPIO 就能当串口，要么走 USB 转串口，要么占用调试 UART，要么找到 UART 测试点。”
- “断线超时回 0 危险；建议用你已经在量的 5V 主电源判断：5V 在、串口断了 → 100%；5V 不在 → 0%。”

## 九、分歧与待确认（2026-11-16）

| 点 | 合作方说法 | 实际/判断 | 结论 |
|---|---|---|---|
| MCU 要硬件 PWM | 单片机靠定时器翻转 IO 做不到那么快 | 对。风扇 PWM 频率高，需要硬件 PWM | ✅ 合作方对 |
| SO8 引脚够用 | 除了 RX/TX/PWM 还能多俩脚，有 ADC | 对。8 脚够用，ADC 可测 5V | ✅ 合作方对 |
| SoC 侧“随便两个 GPIO 配成 RX/TX” | 让我们把两个 GPIO 配成串口 | **错。RK3326 的 UART 是固定引脚**；四个空闲脚 32/33/36/41 都不是 UART | ❌ 合作方错，我们对 |
| “调试 UART 跟咱们不冲突” | 机器本身的 RX/TX 是调试用的，不冲突 | 只有**不用调试 UART**时才成立；用 UART1 接风扇就是冲突 | ⚠️ 看方案 |
| 3 秒没数据回 0 | UART 模式超时输出 0% | 软件崩了/线断了风扇停，可能过热 | ⚠️ 建议改：5V 在→100%，5V 不在→0% |
| 通信格式他定 | 他做完单片机给格式 | 可以；我们需波特率/帧/校验/单位 | ✅ 等合作方 |

### 还需要用户跟他说清楚的

1. **SoC 侧串口走哪条**：USB 转串口（最稳）/ 调试 UART1（牺牲调试口）/ 找 UART 测试点（58/59、60/61、76/78、97/98）。
2. **断线保护**：超时回 100% 还是回 0？建议用 5V 主电源判断。
3. **协议细节**：波特率、8N1、3.3V 电平、帧头/长度/校验、5V 量程、转速单位。
4. **风扇类型**：2 线还是 4 线？有没有 FG？没有 FG 的转速怎么处理。

### 我的判断

- **架构上合作方对**：MCU 做硬件 PWM、UART 收目标、ADC 测 5V，这个分工合理。
- **SoC 引脚上我们对**：RK3326 不是单片机，UART 不能随便映射到任意 GPIO；四个空闲脚都不是 UART。
- **超时保护上我们对**：回 0 有热风险，应该用 5V 主电源或 NTC 做失效安全。
- 我之前也报错过一次（把 UART3 M1 的 46/47 当成 42/43，后来发现 46/47 是十字键），已在上面表格里改正。
